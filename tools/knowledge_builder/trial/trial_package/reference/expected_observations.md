### PDF側の想定される章・段落分割(実Adapter出力で検証済み・2026-08-02修正)

**是正: 本節は当初「章見出しだけがsectionになる」という誤った想定で書かれていましたが、
実際にAdapter(`pdf_direct_adapter.js`)の出力を再集計した結果と食い違っていたため、
実測値に合わせて書き直しています。** `matchFixedHeadingLine()` は「第N章」のような章見出しと、
「N.N タイトル」のような番号付き項目見出しの両方を、同じ階層のsection(見出し)として
フラットに認識します(sectionの入れ子はありません)。そのため、章見出し自体に加えて
「2.1 車室温度」のような各項目の見出し行もそれぞれ独立したsection Nodeになり、

`train_hvac_customer_requirements.pdf` の実際のsection一覧(見出しとして検出された14件、
出現順):

2. 2.1 車室温度 ← 直後の本文段落がstatement 1件になる
3. 2.2 冷房能力
4. 2.3 暖房能力
5. 2.4 騒音
6. 2.5 電源条件
7. 2.6 振動
8. 2.7 除湿性能
9. 第3章 保守・安全要求 ← 空section(statement 0件)

11. 3.2 安全性
12. 3.3 質量

上記のうち2の章見出し(第2章・第3章)だけが空sectionで、残り12件の項目見出しはそれぞれ

### 想定されるCandidate件数の目安

- 実際に検証した結果、**33件** のCandidateが生成された。上記の想定7組は比較的高い信頼度

- これはExcelとの組み合わせ(ケースA)より候補数・ノイズが多くなる傾向がある。これは

- 候補数が多いこと自体が不具合ではないが、Graphの「理解しやすさ」評価に影響しうる点は
  留意して観察するとよい。

## タイトル表示の既知差異について

- PDF由来のNodeは `title` と `text` が同じ値になる(Adapterの仕様上、PDFは常に一致)。
- Excel由来のNodeは `title` が先頭セルの値のみ(例:「車室温度」)、`text` は
  「見出し: 値」を連結した複合文になる。このため同じ項目でもPDF側とExcel側で
  画面上のタイトル表示の見え方が異なる。これは既知の仕様差であり、不具合ではない。
