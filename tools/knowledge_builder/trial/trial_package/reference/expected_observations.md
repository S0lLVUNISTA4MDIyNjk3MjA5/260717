# 想定される観察内容(運用者向け参考資料)

**この文書は運用者(試用を企画・分析する側)向けの参考資料です。評価者に提示する必要はありません。**

**これは完全なRelation Candidateの正解表ではありません。** ここに書かれているのは、あくまで
「試作データを設計した際に想定した、ざっくりとした目安」です。実際にツールを動かした結果と
完全に一致することを保証するものではなく、また「この通りに候補が出なければ不具合」という
判定基準として使うものでもありません。人が試用した際の印象を評価するための参考値です。

## ケースA: PDF x Excel

- 文書A: `train_hvac_customer_requirements.pdf` (顧客要求仕様書、第2章・第3章、12項目)
- 文書B: `train_hvac_design_review.xlsx` (設計レビュー表、1シート「設計レビュー」、13行)

### 明確に対応すると想定される項目(目安7組)

| 文書A(顧客要求) | 文書B(設計レビュー行) |
|---|---|
| 2.1 車室温度 | 車室温度 |
| 2.2 冷房能力 | 冷房能力 |
| 2.3 暖房能力 | 暖房能力 |
| 2.4 騒音 | 車室内騒音 |
| 2.5 電源条件 | 電源仕様 |
| 2.6 振動 | 耐振動性能 |
| 3.1 保守性 | フィルタ保守性 |

### 部分的に関連すると想定される項目(目安2〜4組)

- 2.7 除湿性能 ⇔ 除湿・温湿度制御(顧客要求は除湿性能を明記、設計側は「今後検討」として保留中の関係)
- 3.2 安全性 ⇔ 保護構造・絶縁(安全性要求のうち感電・火傷防止の一部にのみ設計側が対応)
- 3.5 電磁両立性 ⇔ EMC対策(規格準拠の方向性は一致するが、設計側は検討中で具体値がない)

### 明確な対応がないと想定される項目(目安2〜3件)

- 文書B側のみ: 外装塗装仕様、製造工程、梱包仕様(顧客要求には対応する項目がない、製造・物流側の都合による項目)
- 文書A側のみ: 3.3 質量、3.4 耐久性(設計レビュー表には対応する行がない)

### PDF側の想定される章・段落分割

- 第2章 環境性能要求(見出しのみ、本文なしのsection) → 2.1〜2.7 の7項目
- 第3章 保守・安全要求(見出しのみ、本文なしのsection) → 3.1〜3.5 の5項目
- 見出し行の直後に段落が続かない章見出し(第2章・第3章)は、`paragraphs: []` の空sectionとして
  扱われる(Adapterの既存仕様どおり)。

### Excel側の想定される見出し行・データ開始行

- ヘッダー行: 1行目(要求項目/設計方針/設計値/単位/根拠/確認状況)
- データ開始行: 2行目
- 自動検出(`detectHeaderAndDataStart`)は `confidence: 'high'` で `headerRow=1, dataStartRow=2` を返す想定。

### 想定されるCandidate件数の目安

- 実際に本ツールの純関数(既定の `minScore=0.12`)で検証した結果、**7件** のCandidateが生成され、
  上記「明確に対応する7組」がすべて候補として現れることを確認済み。
- 信頼度(confidence)はおおむね 0.08〜0.18 の範囲(PDF側は短い自然文、Excel側は
  「見出し: 値」を連結した長い複合文のため、文字列的な類似度は高くは出にくい)。
- 部分関連・無関係の項目からは、誤って候補が生成されないことを確認済み。

### 想定されるNode数

- 文書A(PDF): document 1 + section 2(空) + statement 12 = 15 Node
- 文書B(Excel): document 1 + section 1 + statement 13 = 15 Node
- Graphが過度に複雑にならない範囲(候補7件、Node合計30件程度)を想定。

## ケースB: PDF x PDF

- 文書A: `train_hvac_customer_requirements.pdf` (ケースAと同じファイル)
- 文書B: `train_hvac_unit_purchase_specification.pdf` (購入仕様書、第1〜3章、13項目)

### 明確に対応すると想定される項目(目安7組)

| 文書A(顧客要求) | 文書B(購入仕様書) |
|---|---|
| 2.1 車室温度 | 2.1 温度性能 |
| 2.2 冷房能力 | 2.1 温度性能 |
| 2.3 暖房能力 | 2.2 暖房性能 |
| 2.4 騒音 | 2.3 騒音性能 |
| 2.5 電源条件 | 3.1 電源仕様 |
| 2.6 振動 | 3.3 耐振動構造 |
| 3.1 保守性 | 3.4 保守性 |

### 部分的に関連すると想定される項目(目安2〜4組)

- 2.7 除湿性能 ⇔ 2.4 除湿性能(購入仕様側は「別途協議」で具体値が保留)
- 3.3 質量 ⇔ 3.2 外形・質量(質量の数値は近いが、外形寸法は別紙参照で本文に含まれない)
- 3.5 電磁両立性 ⇔ 3.7 電磁両立性(方向性は一致するが購入仕様側は「別途協議」で詳細未定)

### 明確な対応がないと想定される項目(目安2〜3件)

- 文書B側のみ: 1.1 適用範囲、1.2 参照規格、3.5 検査項目、3.6 保証期間
- 文書A側のみ: 3.4 耐久性(購入仕様書には走行距離換算の耐久性要求に対応する項目がない)

### 想定されるCandidate件数の目安

- 実際に検証した結果、**33件** のCandidateが生成された。上記の想定7組は比較的高い信頼度
  (confidence 0.25〜0.42)で候補に含まれる一方、PDF同士は自然文どうしの比較になるため、
  「〜とすること。」のような文末表現や「外気温」「車室内」等の共通する定型語句の影響で、
  本来無関係な組み合わせにも低い信頼度(confidence 0.07〜0.19付近)の候補が多数生成される。
- これはExcelとの組み合わせ(ケースA)より候補数・ノイズが多くなる傾向がある。これは
  Relation Candidate Engineの文字bigram類似度計算の既知の性質であり、意味を理解した
  マッチングではないことを人が実感する材料として、むしろ試用の観察点として有用と考えられる。
- 候補数が多いこと自体が不具合ではないが、Graphの「理解しやすさ」評価に影響しうる点は
  留意して観察するとよい。

### PDF側の想定される章・段落分割

- 文書B: 第1章 総則(見出しのみ) → 1.1〜1.2、第2章 性能仕様(見出しのみ) → 2.1〜2.4、

  README/ガイドで案内している。

## タイトル表示の既知差異について

- PDF由来のNodeは `title` と `text` が同じ値になる(Adapterの仕様上、PDFは常に一致)。
- Excel由来のNodeは `title` が先頭セルの値のみ(例:「車室温度」)、`text` は
  「見出し: 値」を連結した複合文になる。このため同じ項目でもPDF側とExcel側で
  画面上のタイトル表示の見え方が異なる。これは既知の仕様差であり、不具合ではない。
