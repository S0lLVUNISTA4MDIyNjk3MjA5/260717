# 既知の制限 — 仕様書PDF → JSON 変換 α版 v0.1.0-alpha

## 母体

`README.md`の「母体」を参照してください。コミット`9fb473f96bac7df52a27282aa4e48257aa7a5274`上の
`tools/spec_to_json_conversion_tool_v1.18.html`（blob `8dbdd584277176f935295b0072d08837eae0e328`）を
基準としています。このコミットで基準ツールへ追加された「照合用+数量注釈JSON」出力機能は無改変のまま
保持していますが、本α版の評価対象外です。

## 対応対象

- テキスト層を持つ単一PDFの読込・変換（PDF.js 3.11.174によるテキスト抽出、基準ツール既定の
  章・節見出し規則に基づく構造化。`extractPdf`/`extractPdfLayout`/`buildJsonFromLines`を無改変で使用）
- 段落・箇条書き・簡易表（2列以上に分かれた行の連続）の抽出
- JSON構文検証（`JSON.parse`が例外なく成功するかの機械的確認。意味的な正しさの保証ではありません）
- 変換件数（基準ツール既存の`v12ReviewCounts().total`＝段落・箇条書き項目・表の行の件数）・
  警告件数・未確認件数の集計表示
- 抽出結果とPDF原文とのテキスト一致検査（基準ツール既存の`scoreAgainstPdf`/`computeMatches`を
  そのまま利用）

## 警告件数・未確認件数の定義（α版が読み取る既存指標）

- **警告件数**：基準ツール既存のPDF原文突き合わせ機能（`computeMatches`/`matchResults`）が
  「部分一致（△）」または「不一致（✕）」と判定した項目数です。値の意味的な正しさを判定するもの
  ではなく、抽出結果がPDF原文中に見当たらない/一部しか見当たらないことの機械的な指標です。
- **未確認件数**：基準ツールの確認状態管理（`v12ReviewCounts().unreviewed`）で未確認のままの項目数
  です。変換直後は全項目が未確認のため、通常は変換件数と一致します。
- いずれも基準ツールが既に持つ機能を読み取って集計しているだけで、集計ロジックの追加以外、
  変換自体・確認状態管理自体には一切手を加えていません。

## オフライン動作について

`README.md`の「CDN対応について」を参照してください。CDN依存（PDF.js・tiny-segmenter）はローカル
同梱に変更済みで、対応対象範囲（構造化PDF・表入りPDF）では外部ネットワーク接続なしで動作すること
（外部リクエスト0件）を、全外部リクエストを遮断した状態でのスモークテストで確認しています
（`SMOKE_TEST_REPORT.md`参照）。

## 抽出不能PDFの扱い（本α版が明示的に確認済みの挙動・commit blockerではありません）

テキスト層からの抽出文字数が不足するPDF（スキャン画像のみのPDF、完全な空白ページ等）に対しては、
基準ツールの既存仕様により自動的にOCR（Tesseract.js）へのフォールバックが試みられます。**α版では
OCRを対応対象外とすることを明示的に許容しており**、Tesseract.jsは意図的に同梱していません。この
場合、OCR読み込み自体が失敗し、「生成に失敗しました: OCRエンジン（Tesseract.js）の読み込みに失敗
しました。インターネット接続を確認してください。」という明示的なエラー通知が表示されます。変換前の
状態（`data`）は変更されず、α評価パネルが変換失敗を成功として表示することもありません
（`samples/sample_input_unextractable.pdf`で確認済み）。

このケースでは、Tesseract.js CDNへの外部リクエスト試行が1件発生し、遮断されます。これは対応対象外の
OCR経路を通ったことによる想定内の挙動であり、対応対象範囲（構造化PDF・表入りPDF、PDF.js本体・
worker・cmaps・standard_fonts・tiny-segmenterで完結する経路）における「外部リクエスト0件」という
受入条件とは別のものとして扱っています。詳細は`SMOKE_TEST_REPORT.md`を参照してください。

## 本α版に含まれないもの（対象外）

- OCR（スキャン画像PDF対応）。Tesseract.jsは意図的に同梱していません。
- 生成AIによる埋め込み類似度比較（`@huggingface/transformers`を使用する照合ツール向け機能）
- 複雑な図面解析・非定型レイアウト・入れ子の表・多段組みレイアウトへの対応保証
- 照合ツール（`json_ab_trace_matching_tool`）との連携、版間比較機能の評価
- サーバー保存・認証・複数人での同時編集
- 母体に含まれる「照合用+数量注釈JSON」出力機能自体の精度評価

## 未検証・未実施の事項

- STEP 2の生成AI連携は、プロンプト／JSONのコピー・保存と回答JSONの貼り付け取込だけを行います。
  外部AIサービスへの自動送信、モデル呼出し、認証、AI回答の正しさの保証は含みません。
- AI回答取込時は件数・固定ID・内容ハッシュ・原文を検証しますが、照合タグの意味的妥当性は利用者が
  STEP 3および検証機能で最終確認してください。AI確認済は人手確認済とは別の情報です。
- Microsoft Edge（Edge独自ブランドでの実機起動）での手動確認は、本チェックポイント作成環境に
  Edge実行ファイルが存在しないため実施していません。Chromiumエンジンでの自動スモークテストのみ
  実施しています（`SMOKE_TEST_REPORT.md`参照）。EdgeはChromiumベースのため挙動は近いと考えられ
  ますが、これは推測であり実測ではありません。
- 全帳票・全レイアウト（複雑な図面、非定型ヘッダー、多段組み等）を網羅した精度評価は実施していません。
  同梱の代表サンプル3件（構造化・表・抽出不能）のみを対象に検証しています。
- 大量ページ（数十〜数百ページ）での性能・メモリ使用量の評価は実施していません。
- スキャン画像PDF・手書き文字を含むPDFの評価は実施していません（OCR対象外のため）。
