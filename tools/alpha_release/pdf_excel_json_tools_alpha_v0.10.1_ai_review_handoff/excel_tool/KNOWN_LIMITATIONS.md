# 既知の制限 — Excel → JSON 変換 α版 v0.10.1-alpha

## 対応対象

- 単一Excelブック（.xlsx/.xls/.xlsm/.xlsb/.csv、SheetJS 0.18.5が対応する形式）の読込
- シート選択・行列範囲選択、ヘッダー行／データ開始行指定によるExcel→JSON構造変換
  （基準ツール `excel_to_json_conversion_tool_v2.0.8.html` の `convertSheet`/`convertWorkbook` を無改変で使用）
- 結合セルの左上値展開、空白セル自動補完、NULL判定文字の変換など、基準ツールが既に持つ整形機能
- JSON構文検証（`JSON.parse`が例外なく成功するかの機械的確認。意味的な正しさの保証ではありません）
- 変換件数・警告件数・未確認件数の集計表示
- 基準ツールに内蔵の「照合用JSON（Excel行単位）」様式（`trace`モード）適用による、タグ付け・
  `source_row`等を含む出力（様式・タグロジック自体も無改変）
- 照合用JSONと同一スナップショットから生成する数量注釈（quantity-annotation）サイドカーJSONの
  出力（PDF版と共通の抽出ライブラリ・binding-coreを使用）
- PDF版と共通の辞書ファイル`shared/tag_vocabulary.json`の読込・出力時canonicalハッシュ付与

## タグ出力に関する既知の仕様（基準ツール既存仕様・バグではありません）

内蔵様式「照合用JSON（Excel行単位）」を適用した出力では、各レコードのトップレベル `tags` は
「人が確認・確定したタグ」を様式切替をまたいで保持する仕組みのため、確認操作を一度も行っていない
状態では空配列のままになります。様式のタグ付与ルールを実際に適用した結果（提案値）はネストした
`source_record.tags` に入ります。詳細と具体例は `samples/README.md` を参照してください。

## 警告件数・未確認件数の定義（α版独自の集計）

- **警告件数**：結合セル展開・空白補完・NULLトークン置換のいずれかにより、値がそのセル自身の内容
  ではなく自動的に推定・代入された行数です。値の意味的な正しさを判定するものではありません。
- **未確認件数**：変換結果に空欄（空文字・null・省略）を含む行数です。同様に意味的な正しさの判定
  ではありません。
- どちらも基準ツールの `convertSheet()` が既に計算しているセル由来情報（`origin`）をそのまま集計した
  ものです。集計ロジックの追加以外、変換自体には一切手を加えていません。
- 様式（プロファイル）を適用すると、基準ツールの既存仕様により上記のセル由来情報は失われます
  （`currentCellMeta`が空になる）。そのためα版は、直近に得られたセル由来情報（＝生のExcel→JSON構造
  変換の時点）の警告・未確認件数をそのまま保持して表示し続けます。様式適用後に新たに生じうる問題
  （タグの未登録等）はこの2つの件数には反映されません。タグに関する情報が必要な場合は、出力JSON中の
  `tag_policy`・各レコードの`tags`/`unregistered_tags`、および`statistics.unregistered_tags`
  （基準ツールが既に出力している値）を確認してください。

## 数量注釈サイドカー（quantity annotation）に関する既知の制限

- 照合用JSONと数量注釈JSONは、`JSON.stringify`→`JSON.parse`で確定させた単一のスナップショット
  （persisted snapshot）から1操作で生成します。2ファイル目の生成に失敗した場合は「照合用JSON＋
  数量注釈JSONの生成に失敗しました」というエラー表示のみを行い、1ファイル目が先に物理的に
  ダウンロードされていても、その成果物セットを正常な出力として扱いません（利用者は再実行してください）。
- サイドカー内の`dataset_signature`・`content_hash`等は、照合ツール本体（`quantity_sidecar_binding_core.js`）
  と同一の正本ロジックで計算していますが、実際に照合ツールへ読み込んだ際の突合せ結果（bindingの
  `ready`/`diagnostics`）そのものの妥当性評価は、本α版の検証範囲では基本的な整合性確認に限定しています。
- 数量の抽出・単位解釈・区間解釈のルール自体（列役割候補の推定を含む）はPDF版と共通のライブラリを
  そのまま使用しており、Excel特有の列構成・結合セル・複数単位混在シートに対する精度評価は限定的です。

## 共通タグ辞書（shared tag vocabulary）に関する既知の制限

- `shared/tag_vocabulary.json`はPDF版・Excel版で共通の初期辞書です。画面上で許可タグ・別名を編集する
  ことは可能ですが、出力される`tag_vocabulary.vocabulary_sha256`はその時点で有効なタグ集合を都度
  再計算した値であり、辞書ファイル自体のハッシュを固定的にキャッシュしたものではありません。
- 辞書ファイルの読込は、`vocabulary_id`／`vocabulary_version`が空、`allowed_tags`に重複（正規化後の
  重複を含む）、`aliases`の参照先が`allowed_tags`に存在しない等、契約として不正な内容を検出した場合に
  読込全体を拒否します（部分的な取込は行いません）。
- 照合ツール（`json_ab_trace_matching_tool`）側で`vocabulary_sha256`の不一致を検出・表示する機能は、
  本α版の対象外です（別チェックポイントで検討予定）。

## オフライン動作について

基準ツール v2.0.8 は変換ライブラリ（SheetJS/xlsx 0.18.5）をCDN (`cdn.jsdelivr.net`) から実行時に取得
する構成でした。本セッションの検証環境では組織のegressポリシーにより`cdn.jsdelivr.net`への接続が拒否
され、CDN方式のままではオフライン・アクセス制限ネットワークで基準ツールが一切動作しないことが判明し
ました。そのためα版では同一バージョンのライブラリをZIP内へローカル同梱し、相対パス
（`./vendor/xlsx.full.min.js`）から読み込む方式に変更しています。バージョン・SHA-256・ライセンスは
`vendor/VENDOR_NOTICE.md` を参照してください。この変更は読み込み元1行のみで、ライブラリ本体・
変換ロジック本体はいずれも無改変です。

## 本α版に含まれないもの（対象外）

- 照合ツール（`json_ab_trace_matching_tool` / `json_ab_trace_matching_tool_lite`）との連携
- サーバー保存・認証・複数人での同時編集
- 完全な共通TraceRecord化
- 高度なセキュリティ強化（入力サニタイズ強化、CSP強化等）
- 全帳票形式・全レイアウト（結合の入れ子、非定型ヘッダー等）への対応保証

## Fixed in v0.10.1-alpha（本α版で修正済みの過去の不具合）

以下は過去のバージョンで存在した不具合で、**本α版では修正済みであり、現在の制約ではありません**。
履歴として記録しています。

- **Excel AI確認情報の欠落**: `buildTraceOutput()`が照合用JSONを再構築する際、`ai_reviewed`等
  5項目をコピーしていなかった不具合。4系統すべての入力経路で修正済み。
- **Excel quantity sidecar未実装**: v0.10.0時点ではExcel版に数量注釈サイドカーJSON出力機能が
  存在しなかった。PDF版と同一ライブラリ・binding-coreを移植し、照合用JSONと同一スナップショット
  からの1操作出力として実装済み。
- **trace_textへのAI管理フィールド混入**: `text_columns`が全行で空白の場合、`textFromColumns()`の
  フォールバック処理が`ai_reviewed`（既定値`false`）を`trace_text`等へ文字列結合していた不具合。
  修正済み（数値`0`・実データとしての`boolean false`は引き続き意味のある値として保持されます）。

## 未検証・未実施の事項

- STEP 2の生成AI連携は、プロンプト／JSONのコピー・保存と回答JSONの貼り付け取込だけを行います。
  外部AIサービスへの自動送信、モデル呼出し、認証、AI回答の正しさの保証は含みません。
- AI回答取込時は件数・固定ID・内容ハッシュ・原文を検証しますが、照合タグの意味的妥当性は利用者が
  STEP 3および検証機能で最終確認してください。AI確認済は人手確認済とは別の情報です。
- Microsoft Edge（Edge独自ブランドでの実機起動）での手動確認は、本チェックポイント作成環境に
  Edge実行ファイルが存在しないため実施していません。Chromiumエンジンでの自動スモークテストのみ
  実施しています（詳細は同梱の `SMOKE_TEST_REPORT.md` を参照）。EdgeはChromiumベースのため挙動は
  近いと考えられますが、これは推測であり実測ではありません。
- 全帳票・全レイアウトを網羅した精度評価は実施していません。同梱の代表サンプル1件のみを対象に
  変換結果の妥当性を検証しています。
- 大量データ（数千行以上）での性能・メモリ使用量の評価は実施していません。
