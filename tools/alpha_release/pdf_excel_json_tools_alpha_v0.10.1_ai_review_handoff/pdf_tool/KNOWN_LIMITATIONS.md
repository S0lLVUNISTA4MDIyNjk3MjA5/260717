# 既知の制限 — 仕様書PDF → JSON 変換 α版 v0.10.1-alpha

**本ツールは限定評価用のα版です。** 正式な業務用途を意図したものではなく、評価目的以外での
利用は想定していません。

## 母体

`README.md`の「母体」を参照してください。コミット`9fb473f96bac7df52a27282aa4e48257aa7a5274`上の
`tools/spec_to_json_conversion_tool_v1.18.html`（blob `8dbdd584277176f935295b0072d08837eae0e328`）を
基準としています。このコミットで基準ツールへ追加された「照合用+数量注釈JSON」出力機能は無改変のまま
保持していますが、本α版の評価対象外です。

## 対応対象

- テキスト層を持つ単一PDFの読込・変換（PDF.js 3.11.174によるテキスト抽出、基準ツール既定の
  章・節見出し規則に基づく構造化。`extractPdf`/`extractPdfLayout`/`buildJsonFromLines`を無改変で使用）
- 段落・箇条書き・簡易表（2列以上に分かれた行の連続）の抽出
- JSON構文検証（`JSON.parse`が例外なく成功するかの機械的確認。意味的な正しさの保証ではありません）
- 変換件数（基準ツール既存の`v12ReviewCounts().total`＝段落・箇条書き項目・表の行の件数）・
  警告件数・未確認件数の集計表示
- 抽出結果とPDF原文とのテキスト一致検査（基準ツール既存の`scoreAgainstPdf`/`computeMatches`を
  そのまま利用）
- Excel版と共通の辞書ファイル`shared/tag_vocabulary.json`の読込・出力時canonicalハッシュ付与

## 警告件数・未確認件数の定義（α版が読み取る既存指標）

- **警告件数**：基準ツール既存のPDF原文突き合わせ機能（`computeMatches`/`matchResults`）が
  「部分一致（△）」または「不一致（✕）」と判定した項目数です。値の意味的な正しさを判定するもの
  ではなく、抽出結果がPDF原文中に見当たらない/一部しか見当たらないことの機械的な指標です。
- **未確認件数**：基準ツールの確認状態管理（`v12ReviewCounts().unreviewed`）で未確認のままの項目数
  です。変換直後は全項目が未確認のため、通常は変換件数と一致します。
- いずれも基準ツールが既に持つ機能を読み取って集計しているだけで、集計ロジックの追加以外、
  変換自体・確認状態管理自体には一切手を加えていません。

## 共通タグ辞書（shared tag vocabulary）に関する既知の制限

- `shared/tag_vocabulary.json`はPDF版・Excel版で共通の初期辞書です。画面上で許可タグ・別名を編集する
  ことは可能ですが、出力される`tag_vocabulary.vocabulary_sha256`はその時点で有効なタグ集合を都度
  再計算した値であり、辞書ファイル自体のハッシュを固定的にキャッシュしたものではありません。
- 辞書ファイルの読込は、`vocabulary_id`／`vocabulary_version`が空、`allowed_tags`に重複（正規化後の
  重複を含む）、`aliases`の参照先が`allowed_tags`に存在しない等、契約として不正な内容を検出した場合に
  読込全体を拒否します（部分的な取込は行いません）。
- 照合ツール（`json_ab_trace_matching_tool`）側で`vocabulary_sha256`の不一致を検出・表示する機能は、
  本α版の対象外です（別チェックポイントで検討予定）。

## オフライン動作について

`README.md`の「CDN対応について」を参照してください。CDN依存（PDF.js・tiny-segmenter）はローカル
同梱に変更済みで、対応対象範囲（構造化PDF・表入りPDF）では外部ネットワーク接続なしで動作すること
（外部リクエスト0件）を、全外部リクエストを遮断した状態でのスモークテストで確認しています
（`SMOKE_TEST_REPORT.md`参照）。

## 抽出不能PDFの扱い（本α版が明示的に確認済みの挙動・commit blockerではありません）

テキスト層からの抽出文字数が不足するPDF（スキャン画像のみのPDF、完全な空白ページ等）に対して、
基準ツールの既存仕様では自動的にOCR（Tesseract.js、CDNから実行時取得）へのフォールバックが
試みられていました。**α版ではOCRを対応対象外とすることを明示的に許容しており**、Tesseract.jsは
意図的に同梱していません。

Checkpoint 7（offline hardening）以降、この経路は「CDNへ接続を試み、失敗したらOCR未対応として扱う」
という実装ではなく、**CDNへは一切接続せず、即座にOCR未対応として扱う**実装に変更しています
（`loadTesseractJs()`が外部スクリプトタグを生成せず、無条件に拒否を返します）。この場合、
「生成に失敗しました: OCR（Tesseract.js）はこのα版では未対応です。テキスト層からの抽出のみに
対応しています。」という明示的なエラー通知が表示されます。変換前の状態（`data`）は変更されず、
α評価パネルが変換失敗を成功として表示することもありません（`samples/sample_input_unextractable.pdf`
で確認済み）。

このケースでの外部networkリクエスト試行は**0件**です（旧実装では1件のTesseract.js CDNへの試行が
発生し遮断されていましたが、この経路自体を無効化したため試行そのものが発生しません）。対応対象範囲
（構造化PDF・表入りPDF、PDF.js本体・worker・cmaps・standard_fonts・tiny-segmenterで完結する経路）
とOCR未対応PDFのいずれも「外部リクエスト0件」です。詳細は`SMOKE_TEST_REPORT.md`を参照してください。

## 本α版に含まれないもの（対象外）

- OCR（スキャン画像PDF対応）。Tesseract.jsは意図的に同梱していません。
- 生成AIによる埋め込み類似度比較（意味検索・類似比較機能。母体ツールはCDN(`@huggingface/transformers`)
  から実行時にライブラリを取得する構成だが、Checkpoint 7以降、本α版ではCDNへ一切接続せず、
  画面上の該当ボタンを押しても即座に「対象外」エラーを返すよう変更している。外部リクエストは0件）
- 複雑な図面解析・非定型レイアウト・入れ子の表・多段組みレイアウトへの対応保証
- 照合ツール（`json_ab_trace_matching_tool`）との連携、版間比較機能の評価
- サーバー保存・認証・複数人での同時編集
- 母体に含まれる「照合用+数量注釈JSON」出力機能自体の精度評価

## Fixed in v0.10.1-alpha（本α版で修正済みの過去の不具合）

以下は過去のバージョンで存在した不具合で、**本α版では修正済みであり、現在の制約ではありません**。
履歴として記録しています。

- **AI入力JSON生成時の`source_content`欠落**: AI入力JSON保存時、一部レコードで`source_content`
  フィールドが生成されない不具合（ReferenceError由来）があった。全recordで`source_content`が
  存在することを確認済み（`pdf_checkpoint1_verification.js`参照）。
- **数量注釈サイドカーの署名不整合**: 照合用JSON・数量注釈JSONの`dataset_signature`／
  `content_hash`が、照合ツール正本の`quantity_sidecar_binding_core.js`によるbinding時に
  `source_mismatch`等の診断を生じていた問題。実binding coreを用いた検証でdiagnostics 0件・
  `ready === true`であることを確認済み。

## 未検証・未実施の事項

- STEP 2の生成AI連携は、プロンプト／JSONのコピー・保存と回答JSONの貼り付け取込だけを行います。
  外部AIサービスへの自動送信、モデル呼出し、認証、AI回答の正しさの保証は含みません。
- AI回答取込時は件数・固定ID・内容ハッシュ・原文を検証しますが、照合タグの意味的妥当性は利用者が
  STEP 3および検証機能で最終確認してください。AI確認済は人手確認済とは別の情報です。
- **生成AIによる回答・タグ提案は、人手によるレビュー・最終確認を代替するものではありません。**
  `ai_reviewed`（AI確認済み）は`review_status`（人手確認済み）とは別の情報として保持され、
  AI取込によって人手確認状態が変更されることはありません。
- Microsoft Edge（Edge独自ブランドでの実機起動）での手動確認は、本チェックポイント作成環境に
  Edge実行ファイルが存在しないため実施していません。Chromiumエンジンでの自動スモークテストのみ
  実施しています（`SMOKE_TEST_REPORT.md`参照）。EdgeはChromiumベースのため挙動は近いと考えられ
  ますが、これは推測であり実測ではありません。
- 全帳票・全レイアウト（複雑な図面、非定型ヘッダー、多段組み等）を網羅した精度評価は実施していません。
  同梱の代表サンプル3件（構造化・表・抽出不能）のみを対象に検証しています。
- 大量ページ（数十〜数百ページ）での性能・メモリ使用量の評価は実施していません。
- スキャン画像PDF・手書き文字を含むPDFの評価は実施していません（OCR対象外のため）。
